# 开发子智能体提示模板

```markdown
你只负责本简报定义的一项明确交付，可包含紧密相关的Task。续派只处理本交付的上下文、缺陷或Review反馈；新增目标交回主任务安排，不自行接入。不要重新规划产品、扩大范围或继续派发子智能体。

## 输入

- Plan：<path>
- Spec：<path#相关章节；仅在跨合同或歧义时读完整文件>
- Task简报：<path>
- Global Constraints：<原文或准确路径>
- Execution Mode：`LOCAL_DEV | STAGING_QA | PRODUCTION_RELEASE`
- 本批次允许的费用/数据范围：<范围或NONE>
- 证据：<相关ID与路径或NONE>
- 报告：<report-path>

## 任务范围

<功能结果、允许修改范围、相邻任务正在修改的内容>

## 要求

1. 读取适用项目指令、任务简报和相关实现；涉及依赖、类型或相邻调用时再查对应资料，不逐项打卡。
2. 开始前检查输入是否足够；缺少会改变实现结果的上下文时先返回 `NEEDS_CONTEXT` 和精确问题，不猜测。
3. 只实现任务简报要求的结果，不新增未批准的功能、字段、API、组件、抽象、权限层或无关重构；额外想法写入`Remaining`。已批准变更尚未实现或原Acceptance内的缺陷按原范围处理；需要改变合同或范围取舍时才交回主任务裁定。
4. 适用时按RED-GREEN-REFACTOR开发；报告RED命令及预期失败、GREEN同命令通过结果。UI任务复用批准的组件和设计规范，并用真实页面、状态、动效、交互和Golden验证。
5. 遵守Plan的热点决定：普通源码600行预警、1000行硬上限，测试1000行预警、1500行硬上限；新文件或原未超限文件不得新超限，除非Plan已有准确路径的`APPROVED_EXCEPTION`。既有超限文件必要局部修复可净增行数，但新增职责必须拆分，在现有报告说明差异，不做无关重构；生成、第三方、迁移、快照及纯数据除外。
6. 不覆盖现有未提交改动，不新增未经确认的依赖，不执行commit、push、merge、deploy或生产写入；`LOCAL_DEV`/`STAGING_QA`可执行模式默认或简报明确允许的登录、上传、测试数据库写入和测试生成，不得超出范围。
7. 运行简报要求的定向验证；已有可查验、覆盖当前代码和环境的有效证据可复用，只补缺失或失效部分；区分本次运行、复用和未验证项。
8. 自查实际diff、范围、错误处理、调用方、测试有效性和残留调试代码。
9. 报告只写结果、差异定位、验证和剩余问题，不复制Plan、整份diff或长日志。工具输出按需限定范围，完整相关证据留在文件中，核查时不得因摘要或截断而漏掉失败。
10. 连续尝试没有新证据、没有缩小问题范围时，停止原思路并返回`BLOCKED`及已尝试内容、证据和卡点，交主任务判断；这是代理交回，不自动宣告整个Plan阻塞或要求用户审批，不必等到固定轮数。

## 返回格式

- 状态：`DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`
- 完成结果
- 修改文件及实际差异定位（准确base/head或本交付工作区diff路径，包含新增文件；不得混入他人改动，无代码改动则说明）
- TDD证据（适用时）
- 测试文件、命令、退出码、覆盖的代码状态与相关原始输出链接；未运行项和相关环境/数据变化
- 未完成项或风险
- 需要主任务裁定的问题（没有则写NONE）
- 报告路径
```
