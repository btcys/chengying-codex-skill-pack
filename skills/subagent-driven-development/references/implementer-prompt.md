# 开发子智能体提示模板

```markdown
你负责实现一个边界明确的功能批次。不要重新规划产品，不要扩大范围，不要继续派发子智能体。

## 输入

- Plan：<path>
- Spec：<path#相关章节；仅在跨合同或歧义时读完整文件>
- Task简报：<path>
- Global Constraints：<原文或准确路径>
- Execution Mode：`LOCAL_DEV | STAGING_QA | PRODUCTION_RELEASE`
- 本批次允许的费用/数据范围：<范围或NONE>
- 证据：<相关ID与路径或NONE>
- 报告：<report-path>

## 任务范围

<功能结果、允许修改范围、相邻任务正在修改的内容>

## 要求

1. 先阅读项目指令、任务文件、相似实现、依赖和类型。
2. 开始前检查输入是否足够；缺少会改变实现结果的上下文时先返回 `NEEDS_CONTEXT` 和精确问题，不猜测。
3. 只实现任务简报要求的结果，不新增未批准的功能、字段、API、组件、抽象、权限层或无关重构；额外想法写入`Remaining`，发现设计缺陷或范围冲突时停止并返回 `BLOCKED`。
4. 适用时按RED-GREEN-REFACTOR开发；报告RED命令及预期失败、GREEN同命令通过结果。UI任务复用批准的组件和设计规范，并用真实页面、状态、动效、交互和Golden验证。
5. 遵守Plan的热点文件决定：普通源文件600行预警、1000行硬上限，测试文件1000行预警、1500行硬上限；既有超限文件不得增长，只渐进拆分本Task相关职责。只有Plan标记 `APPROVED_EXCEPTION` 的准确路径可以显式放行；生成代码、第三方代码、迁移、快照和纯数据文件除外。
6. 不覆盖现有未提交改动，不新增未经确认的依赖，不执行commit、push、merge、deploy或生产写入；`LOCAL_DEV`/`STAGING_QA`可执行模式默认或简报明确允许的登录、上传、测试数据库写入和测试生成，不得超出范围。
7. 运行简报要求的定向验证，没运行的测试必须明确说明。
8. 自查实际diff、范围、错误处理、调用方、测试有效性和残留调试代码。
9. 报告只写结果、文件、验证和风险，不复制Plan或长篇过程。

## 返回格式

- 状态：`DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`
- 完成结果
- 修改文件
- TDD证据（适用时）
- 测试文件、命令、退出码、覆盖的代码状态与相关原始输出链接；未运行项和相关环境/数据变化
- 未完成项或风险
- 需要主任务裁定的问题（没有则写NONE）
- 报告路径
```
