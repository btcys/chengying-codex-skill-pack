# 执行模式与本地测试权限

用于区分开发/测试操作和正式发布操作。本文件不是新的审批阶段；只在任务需要登录、上传、写入测试数据、调用生成或其他真实页面操作时读取。

## 模式选择

- 用户明确说本地开发、开发环境或本地测试，或普通开发/测试任务未标记生产时，默认使用`LOCAL_DEV`。
- 用户明确说测试环境、QA或预发布验证时使用`STAGING_QA`。
- 用户明确说生产、正式发布或生产hotfix时使用`PRODUCTION_RELEASE`。
- 环境不明时只核对一次服务地址、账号和数据目标；不能确认时标记`ENVIRONMENT_UNKNOWN`，不要逐个动作反复询问。
- 无法验证目标确属本地或QA时，不按`LOCAL_DEV`执行写入或真实页面操作；标记`ENVIRONMENT_UNKNOWN`并暂停高副作用动作。

## 默认权限

### `LOCAL_DEV`

默认允许在项目和测试数据范围内修改代码、启动服务、使用或重置本地测试数据库、登录测试账号、上传测试素材、点击真实页面、调用开发接口和执行测试生成。允许的本地操作不需要逐次确认。

### `STAGING_QA`

默认允许正常登录、上传、保存、刷新、生成和回归测试。涉及付费调用、真实客户数据、破坏性数据操作或部署时，读取本Task的明确范围；超出范围才暂停。

### `PRODUCTION_RELEASE`

不默认执行生产登录、写入、计费、删除、迁移、部署或发布。按发布风险审查、授权和回滚规则处理。

## 费用与凭据

- 用户已明确允许的付费测试，在当前Task授权范围内不重复询问；费用上限不明时只询问一次上限。
- 用户输入密码、OTP或CAPTCHA；Agent在登录成功后继续，不读取、记录或输出Secret。
- 验收记录测试动作、次数、费用和Evidence；不把正常本地操作写成流程失败。

## 仍然保留的边界

本地操作放开不等于可以覆盖用户未提交代码、删除项目文件、擅自commit/push/merge/deploy或连接生产。开始前保留`git status`和现有改动，完成后检查准确diff。本地和QA不因潜在未来风险新增生产级认证、权限、计费或数据防护层；当前Spec或Task已有安全、权限或计费要求仍必须实现和测试。生产级安全审查只在`PRODUCTION_RELEASE`执行。

## 子智能体交接

主任务在brief中传一行`Execution Mode`和必要的费用/数据范围。子智能体可执行模式默认允许的操作，只禁止生产和超出该范围的副作用；不重新索要完整对话授权。
