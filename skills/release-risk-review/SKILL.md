# 正式发布风险审查

这是发布门禁，不是开发阶段的常态Review。

## 审查范围

- 第一次正式发布：审查完整候选版本及其运行边界。
- 后续正式版本：审查上一个生产版本到当前候选版本的增量diff和受影响风险面。
- 生产hotfix：只审修复范围、回归面、部署与回滚路径。

## 必查风险

- 身份、权限、租户隔离和资源归属；
- 数据迁移、破坏性写入、备份与恢复；
- 计费、额度、退款和重复请求；
- Secret、日志、隐私和用户内容；
- 外部API失败、重试、幂等和限流；
- 性能、容量、队列、超时和可观测性；
- 部署顺序、兼容性、feature flag与回滚；
- 商业关键路径和用户资产完整性。

## 方法

1. 确定生产基线、候选commit、版本和部署目标。
2. 阅读发布范围、变更diff、迁移、配置、依赖和验证证据。
3. 只报告有证据且与本次发布相关的问题；不要把一般性改进伪装成阻断项。
4. 风险分为 `BLOCKER`、`HIGH`、`MEDIUM`、`LOW`，说明证据、影响、触发条件和最小处理建议。
5. 给出结论：`PASS`、`PASS_WITH_ACCEPTED_RISK` 或 `BLOCKED`。

输出到 `docs/releases/<version>/release-risk-review.md`。残余风险需要用户明确接受；本Skill不执行修复、部署或发布。
