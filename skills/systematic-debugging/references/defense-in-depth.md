# 分层防御验证

修复无效数据引起的Bug时，只在一个入口检查可能被其他调用路径、重构或mock绕过。先追踪数据流，再在真正需要的层级建立互补保护。

## 四层

1. **入口验证**：在API或用户输入边界拒绝明显无效值。
2. **业务验证**：确认数据对当前操作有意义，保护领域不变量。
3. **环境保护**：在测试、生产或受限目录中阻止危险副作用。
4. **诊断信息**：在关键操作前记录足以追踪来源的上下文，不记录Secret或隐私。

## 使用方法

1. 找到坏值最初产生的位置；
2. 列出它经过的信任边界；
3. 只在能承担明确责任的层级添加验证；
4. 为每层设计绕过上一层的测试；
5. 保持错误信息可行动且不泄漏敏感信息。

分层防御不是到处复制同一判断。每层必须捕获不同失败类别；如果第二层没有独立职责，就不要机械增加。
