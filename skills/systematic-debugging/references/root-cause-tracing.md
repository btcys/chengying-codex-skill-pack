# 根因回溯

从失败点向上追踪，不要只在堆栈最底部修补。

## 方法

1. 写出失败函数收到的错误值和正确值。
2. 找到调用它的上游位置，记录该值如何产生或转换。
3. 在边界加入最小诊断信息：来源、关键标识、时间、状态和结果；不得记录Secret或敏感数据。
4. 重复向上追踪，直到找到第一个错误值或错误状态被创建的位置。
5. 在来源处修复，并在合同边界添加必要验证，避免静默传播。

## 多层系统示例

```text
浏览器事件正确
→ 请求payload正确
→ API解析错误       ← 第一次变错
→ 服务收到错误值
→ 数据库写入错误值
```

修复API解析，而不是在数据库层把错误值猜回去。

## 证据要求

每个结论至少引用一种可复核证据：失败测试、日志、断点值、网络请求、数据库查询、最小复现或版本diff。相关性不等于因果，必须通过单变量实验验证。
