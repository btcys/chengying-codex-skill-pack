# UI验收检查表

这是 6.2 UI 验收的轻量分级检查，不是新的 Skill 或审批阶段。

## 快速检查（普通小改）

适用于按钮、文案、颜色、间距、局部布局或已有组件状态修正。必须真实打开页面检查一遍，但不启动 Visual Companion，也不查外部参考。

- 读取相关 `Design-Brief.md`、设计域和当前 Spec；没有全局变化时不修改 Design-Brief。
- 在实际视口和本次相关主题下检查布局、Token、组件复用、状态、文案和溢出。
- 只覆盖本次影响的默认、hover/focus/pressed、disabled、loading、empty 或 error 状态。
- 发现问题做最小修复，修后再快速检查一遍；没有真实页面证据不能报告 UI PASS。

## 完整检查（新页面/大改版）

适用于新页面、新入口、跨页面规则、公共组件/Token变化、项目没有 Design-Brief，或用户连续两轮明确不满意。

1. 先写可判对错的标准：实际尺寸、主题/底色、内容边界、状态和可观察结果。
2. 在真实页面、真实视口、真实内容和相关主题下渲染；图标/图片放入实际载体检查。
3. 逐项检查层级、间距、字体、颜色、组件、状态、动效、响应式、无障碍和文案；需要时放大检查细节，但不能代替实际尺寸检查。
4. 用能解释问题的最小改动修复，一次优先只改一个主要变量。
5. 每次修复后重新走第 2～3 步，并检查是否过冲或破坏另一主题/状态。
6. 通过后把结果、视口、主题、截图 Evidence、最终参数写回当前 Spec；跨页面或全局规则才更新 `Design-Brief.md`。

## 外部参考

只有以下情况才查外部设计参考：新项目没有 Design-Brief、新页面没有现成模式、现有规范无法判断，或用户连续两轮明确不满意。已有规范清楚且只是普通小改时不查。

外部参考只能帮助比较结构、密度、交互和动效逻辑，不能覆盖已批准的 Design-Brief、Spec、Golden 或产品事实。

## 证据与完成

- 记录真实入口、视口、主题、状态和截图 Evidence ID；不能用“应该没问题”替代证据。
- 代码、接口、状态或数据结构改动后，受影响的旧 PASS 自动失效，必须重新检查。
- 未完成真实页面检查只能报告“开发完成，待真页验收”。
